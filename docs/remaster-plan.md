# PC Web WASM 全面重制实施计划

状态：规划中，尚未完成 Web 可玩验证、付费素材生成或上线。
日期：2026-09-09。目标仓库：fran0220/ioq3；发布平台：Origin Game。

配套工作包：[引擎与玩法](plans/wasm-engine-remaster.md)、[全资产生产](plans/remaster-asset-pipeline.md)、[发布与长期验收](plans/remaster-release-validation.md)。本文为主计划；工作包保留的不同性能数字和技术建议属于实验候选，以本文统一决策为准。

## 1. 产品边界与待确认事项

- 仅 PC 浏览器，键鼠为主，不做移动端、触摸操作或移动画质适配。
- 首选保留 ioq3 C/C++ 引擎、共享玩法和碰撞代码，经 Emscripten 3.1.58 编译为 WASM；不引入 Three.js。
- WASM 执行 CPU 代码，画面由改造后的 GL2 渲染器经 WebGL2 提交；保留少量 JS/HTML 负责浏览器和平台接口。
- 复刻运动、武器、拾取、死亡重生、计分、胜负和比赛循环。基础 Quake III Arena 的 FFA、Tournament、Team DM、CTF、Bot、在线多人均纳入规划，不因制作分期而删减。Team Arena/其他 Mod 是否包含，需单独确认。
- 重做全部最终可见/可听内容：环境、角色、武器、拾取物、材质、光照、动画、特效、声音、音乐、UI 与宣传素材。
- 内容总量以获批清单为准；未冻结地图、角色、模式和原型参考范围前，不承诺“全部原版内容已覆盖”。
- 原版地图、角色、名称等再分发权尚未确认。重新生成外观不能替代授权。用户需要选择授权重制，或接受独立世界观与原创地图的同类玩法作品；后者不等于原地图完整复刻。
- 付费生成预算需明确首批上限、总预算上限和超额规则；不在预算缺失时启动无上限批量生成。
- 发布属于用户提出的最终目标，但仅在权利、质量、产物与身份门禁通过后执行。多人服务器等共享基础设施的部署/费用另行确认。

## 2. 当前事实与不能预设的能力

- 工作区没有发现 PK3、BSP、MD3、IQM 或 glTF 游戏资产。Web 示例配置里的 pak 路径不是已提供的数据。
- `.agents/setup` 目前只配置 native Debug；Web CI 固定 Emscripten 3.1.58。本轮检查没有找到 PATH 中的 emcc。
- `cmake/platforms/emscripten.cmake` 已有 Web 构建，当前为 256MB 内存、允许 WebGL1–2、关闭独立服务端构建。
- `code/web/client.html.in` 是示例启动页，默认 `net_enabled 0`，还不是经过平台验证的正式启动器。
- GL2 有法线/高光贴图、实验性 PBR、HDR、阴影等代码；文档说明部分特性不支持 OpenGL ES。需分别证明 WebGL2 可用性，不能照搬原生特性清单。
- 已核对 `tr_extensions.c`：GLES 分支提前 `goto done`，跳过后面的 framebufferObject、textureFloat 等初始化；`tr_fbo.c` 的 FBO/HDR 依赖这些能力。M2 必须补齐 ES3 能力接入并做运行验证，不只是修改画质 cvar；实际浏览器上下文版本也尚未验证。
- 模型加载器支持 IQM，但玩家表现仍有 MD3 分段和 tag 约定。支持格式不代表支持新角色动画体系，更不代表直接支持生成服务返回的 GLB。
- Origin Game 网关是制作/AI 服务，不是 Quake UDP 联机服务器；生成接口存在不证明当前账号、模型额度或输出质量。

## 3. 系统边界

运行时：HTML/JS 启动与平台适配 → WASM 引擎/游戏模块 → WebGL2、浏览器输入与音频。

制作时：资产清单 → 风格/原型图 → 审核 → 网关 3D/音频生成 → Blender 修复与制作 → 引擎格式导出 → 验证 → 版本化 PK3/资源包。

保留 `code/game` 的规则与共享运动、`qcommon` 的碰撞及协议语义。主要重制责任位于 `renderergl2`、`cgame` 的表现部分、Web 启动层及离线资产工具。

手感分成两个独立验收域：

1. 规则手感：速度、摩擦、空中加速、台阶、射速、伤害、击退、火箭跳等，不以美术需求改动。
2. 表现手感：镜头/武器摆动、枪口与命中特效、声音同步、动画混合、鼠标映射和呈现延迟，重新制作和调试。

任何动画必须服从游戏事件时序，不能增加开火延迟或凭空添加换弹机制。不要用平滑插值掩盖命中/碰撞错误。

## 4. 工作包与阶段门禁

### M0：立项与基线冻结

交付：版本/模式/地图/角色清单、授权台账、画风规范、预算规则、目标设备矩阵、测试输入与预期结果规范。

建立固定时间步/输入序列参考，记录地面和空中运动、坡面、阶梯、跳跃、传送、拾取、爆炸击退和完整比赛循环。跨 native/WASM 浮点误差制定有理由的容差，不承诺天然位级一致。

权利未解决时，可以制作原创的程序化测试房间和测试几何以验证技术；不能把该测试房间视为用户要求的最终地图替代品。

门禁：范围、参考合法性和首批生成预算确认后，才能生成针对最终原作内容的付费资产。

### M1：可复现 PC Web 引擎基座

固定工具链并纳入 orb setup；构建 Release WASM 与游戏模块。使用合法测试包验证主菜单、地图进入、移动、武器、Bot 和一局结束后重新开始。

制作正式根 `index.html` 启动器：相对路径、manifest、资源错误/重试、加载进度、首个可玩帧 ready、全屏、锁鼠、失焦释放、音频解锁与恢复、配置持久化、键位与鼠标设置、窗口缩放。

决定资源包粒度，区分公共包、模式包和地图包；测量下载/ArrayBuffer/虚拟文件系统/GPU 上传的峰值内存，不仅统计 WASM heap。浏览器缓存不能当作保证存在的永久磁盘。

门禁：standalone 与平台 iframe 两种环境均可完成闭环；刷新、失败下载、无平台 SDK、Esc/Alt-Tab、重新锁鼠、音频恢复全部通过。无最终资产时，只报告技术测试通过，不报告游戏完成。

### M2：浏览器渲染与资产格式契约

用受控材质/模型测试场景逐项验证 WebGL2：光照与色彩空间、normal/specular/PBR、HDR/tonemap、透明排序、粒子、阴影、骨骼动画、纹理压缩和 GPU 上下文恢复。

优先升级既有 renderer，不并行另写 WebGPU 渲染器。现代 glTF metallic-roughness 材质与引擎材质语义须明确转换，不能直接重命名通道。

角色运行时优先评估 IQM 骨骼格式；制定统一骨架、挂点、上下身动作和事件接口。若现有格式不能满足需求，以实际缺口决定扩展，先验证再量产。

GLB/`.blend` 是制作中间件/源文件，最终 runtime 格式由此阶段冻结。地图保留 BSP/PVS、实体及碰撞语义；视觉装饰分块并关联可见性，不能把整图简单转换成单个大模型。

门禁：同一角色与武器样本完成生成、Blender、引擎导入、动作、材质、特效和性能验收；资产流水线与引擎共享一份版本化接口规范。

### M3：完整代表性关卡

选择一张获授权且覆盖高低差、跳台/传送、远近交火与代表性材质的地图。贯通全套环境、角色、第一/第三人称武器、拾取物、特效、音效、HUD、Bot、胜负与重开。

不是只做宣传截图。检查跳跃路线、视线、武器碰撞、敌人辨识、声音定位、动画时序、首次加载和长时间游玩。

门禁：达到画风和性能标准，规则回归没有未经批准的偏差，得到单资产/单地图的实际成本、返工率和工期数据，之后更新全量排期。

### M4：全资产批量重制

按地图和资产族分批，公共材质/组件优先；每批独立验收、提交和资源版本发布。资产不能先全部生成再一次性导入。

全量覆盖清单：建筑模块、地面/墙顶、门/机关、装饰、天空/背景、角色及变体、第一人称手臂/武器、第三人称武器、投射物、弹药/血甲/强化道具/旗帜、粒子/贴花/传送效果、角色/武器动画、脚步/武器/环境/界面音频、播报、音乐、字体/HUD/菜单/图标、封面/海报/截图。

每张地图分别验收视觉、碰撞、实体、PVS、Bot 导航与性能。视觉改动不应无意改变出生点、物品计时、掩体或跨越路线。

门禁：所有获批清单项具有来源、批准状态和引擎内检查证据；不允许最终包残留无权分发的占位素材。

### M5：多人、性能与完整回归

多人传输验证从 M1/M2 并行开始，不等到全美术完成。保留权威服务端与客户端预测语义，单独验证浏览器连接传输/桥接；不预设兼容现有公开原版服务器。

完成大厅/创建加入/断线重连/比赛切换所需产品流程，明确服务端部署、费用、鉴权、消息限额和基础滥用防护。

用多客户端测试不同延迟、抖动、丢包、输入洪泛、掉线与服务重启；检查状态纠错、伤害归属、比分和地图切换。Bot 的 AAS/脚本等数据也须合法且随对应地图正确交付。

门禁：全部模式/地图通过玩法矩阵，目标真实 PC 通过性能矩阵；orb 中软件渲染的 FPS 不能作为用户硬件的性能结论。

### M6：发布与迭代

准备根 index、相对资源、许可证、对应 GPL 源码及构建说明、资产来源、封面/海报/截图、构建版本与变更说明。生产包不含凭据、原始 Blender 文件、node_modules 或意外测试数据。

读取发布时的最新平台规范，始终使用根 `.origingame-deploy.json` 的 og-atlas 身份；不重新选创作者，不盲用默认 protected 许可证模式。

全部门禁通过后执行用户要求的首次发布，保存返回的 gameId/URL。随后在真实平台嵌入页面复测；未来版本更新同一 gameId。

保留经验证的上一版完整包、源码与 manifest；回退通过受支持的版本更新/重新部署流程完成，不假设平台存在未验证的一键回滚。公开上线和底层基础设施修改不是同一个授权范围。

## 5. 原型图 → 3D → Blender 的生产规范

每个场景先制作整体风格/布局原型，再拆分组件；每个需要生成的独立 3D 资产都有获批参考图。重复实例共用资产原型，不为同一管道的每次摆放付费生成。

原型图包括：资产 ID、用途、尺度参照、正/侧/背视图或必要多视图、材质分区、关键挂点、不能改变的轮廓、目标复杂度。多视图必须来自同一批准设计，不拼接相互矛盾的图。

生成输出只算候选。Blender 阶段负责清理、拓扑、三角化、尺度/坐标/原点、UV、纹理烘焙、法线、LOD、碰撞代理、绑定、权重、动作和导出检查。静态道具和角色使用不同处理配置，禁止静态导出器剥离角色骨架/动画。

Hunyuan texture-only 等工作流可能重建 UV，且要求无骨架输入；相关生成/贴纹理应在最终绑定前完成。Meshy 预设动画不等于完整战斗动作库。第一人称动作和游戏事件同步单独制作。

贴图、特效、UI 和声音使用适合其类型的分支，不强迫所有素材经过 3D 生成。声音按声音设计规格生成、审听、剪辑、响度规范化和循环检查；特效还需要引擎程序和时序配置。

资产 manifest 最少记录：ID、类别、目标地图/槽位、参考来源/授权、原型版本、生成模型/请求 ID/成本、输入输出 hash、Blender 版本与脚本版本、导出版本、三角形/骨骼/贴图预算、审批状态、引擎检查结果。

任务采用持久化状态和幂等键，提交任务后先记录任务 ID；遇到超时先查询既有任务，不盲目再次付费。下载结果到受控制作存储，不热链临时网关 URL。大源资产与构建产物不随意塞入 Git；选定 LFS 或授权对象存储后明确费用和访问范围。

## 6. 暂定质量预算（待实际设备和样本校准）

- 桌面 Chrome/Edge 为首批主测，Firefox 纳入发布矩阵；Safari 若要承诺支持，必须有真实 macOS 验证，不能由 Chromium 模拟替代。
- 1080p 中档目标：稳定 60 FPS；指定独显设备高刷档目标：120 FPS。记录帧时间 P50/P95/P99 和长帧，不只看平均 FPS。
- 60 FPS 档暂定 P95 帧时间 ≤16.7ms、P99 ≤33.3ms；最终门禁需要绑定 GPU/CPU/内存/浏览器版本与压力场景。
- 特效开关、动态分辨率或画质档不能改判定与输入。竞技画面默认避免遮挡式镜头震动和过度运动模糊。
- 暂以 50Mbps、50ms RTT 测试冷启动：到可玩目标 ≤30s；实测后校准首包、地图包与缓存策略。总包超平台限额时先解决托管方案，不把上传警告当性能验收。
- 30 分钟多局/多地图测试无持续内存增长；记录 WASM、JS、下载缓存及 GPU 峰值，按目标 PC 设硬预算。
- 验收都记录浏览器版本、设备、构建 hash、资产 manifest、实际输入与输出。截图证明视觉检查，不代替交互和玩法测试。

## 7. 并行线程与集成规则

三个 high 线程已完成引擎、资产、上线验收规划，主线程已读取并整合其交付。当前没有资产生产或部署任务在后台运行，也没有创建自动调度。

后续实现按文件所有权拆分：引擎渲染；浏览器启动/平台；离线资产工具；内容资产批次；测试/发布。`cgame`、共享接口、根 CMake 与 setup 由主线程协调，不允许两个线程同时随意修改。

每个工作包注明输入、输出、禁止触碰的他人文件、验收命令和依赖版本。源线程本地 main 不等于 origin/main；跨 orb 的未推送内容通过文件传输/明确集成交付，不能只发消息假定文件已同步。

按阶段小批提交，依用户指导直接推 main，不创建 PR；主线程整合验证后再推共享改动。付费生产按批准批次执行，遇到预算、权利或外部部署阻塞则记录并推进独立工程工作。

## 8. 排期和完成定义

先按 M0 1–2 周、M1/M2 并行 3–6 周、M3 3–6 周建立规划窗口；M4 全量内容 2–6 个月以上，M5 并行贯穿并预留 3–6 周集中收尾，M6 1–2 周。阶段重叠，不能简单相加。

这些是有经验小团队的初始工作量假设，不是 agent 自动运行时长或交付承诺。总工期取决于授权、资产数、返工率、动画质量、联机和真实 PC 验证。M3 完成后用实测吞吐重排。

项目完成需同时满足：获批内容清单全部完成；规则回归通过；所有资产合法并经过引擎内检查；PC 性能和输入音频达标；Bot/多人及比赛闭环通过；平台加载/全屏/锁鼠通过；源码与许可完整；生产 URL 经发布后验证；可回退至已验证版本。

不能把“可编译”“生成了若干模型”“出现一张漂亮截图”或“上传成功”单独视为完成。

## 9. 三个工作包合并后的统一决策

- 首阶段单线程 WASM、WebGL2 目标；pthread/SAB 不是无条件依赖。平台 play 页虽有隔离头，顶层/iframe 隔离链尚未证明完整，线程化需要单独实验。
- 模型：优先验证 IQM 骨骼角色与新表现接口；MD3 用作旧逻辑兼容对照/必要回退，不先把全部重制角色量产成逐顶点动画。最终格式必须经 M2 样件冻结。
- 材质：以 PC Web GL2 的正确实现为交付目标；传统材质可辅助参考对照，但不新增独立 GL1 产品支持承诺。GLB 不直接作为现有引擎可读格式。
- 所有最终 3D 场景组件按用户要求走批准原型图→图生3D→Blender；程序灰盒只用于技术验证。二维效果和声音走对应制作分支。任何工作包对临时测试几何的限制不应阻止不涉及原作数据的工程验证。
- 网络：先实现窄传输边界和受控 WSS 连通性实验，同时比较 WebRTC 无序数据报路径；按丢包尾延迟、浏览器覆盖、TURN/网关成本选择生产方案。不默认改变参考 server tick，不承诺原版公网服务器兼容。
- 性能统一采用第6节的60/120 FPS、50Mbps/50ms冷启动条件；工作包中的144Hz、其他网络条件属于额外压力测试。最终候选增加2小时/30次换图及8小时长时运行，不能只通过30分钟日常检查。
- 加载拆为可操作菜单和入局：菜单目标≤15秒，首场比赛≤30秒，均采用第6节网络条件。平台当前文档有20秒加载遥测，因此尽早交付真正可操作菜单，不能提前发假ready。
